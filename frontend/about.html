About the Project

Online Auction Bid Management System

A multi-tier web application built to demonstrate core Data Structures and Operating System concepts in a practical auction software domain.

What is University Auctions?

University Auctions is a campus-focused auction platform where items are listed, bids are placed in real time, and a concurrent Java engine processes every transaction fairly.

The platform was built as a B.Tech project to explore how foundational CS concepts — Priority Queues, concurrent threads, mutual exclusion — appear in real-world software.

How bidding works

When you place a bid, the frontend sends it to the Python Flask REST API. Flask forwards it to the Java auction engine running as a background process.

The Java engine validates the bid amount (it must be at least the minimum increment above the current highest bid), then inserts it into a PriorityQueue<Bid> that always surfaces the highest valid bid via peek() in O(1) time.

1. Priority Queue Data Structure

Each auction maintains bids inside Java's PriorityQueue<Bid> (binary heap). The comparator orders by descending amount (ascending timestamp for ties), giving O(1) peek and O(log n) insert.

2. Concurrency Control & Synchronization

Multiple bidder threads can arrive simultaneously. The Java engine uses ReentrantLock in AuctionManager.java to enforce mutual exclusion in the critical section — preventing race conditions and guaranteeing mathematically valid bid increments under high concurrency.

Technology Stack

  • Frontend: HTML5, Vanilla CSS, JavaScript ES6 Fetch API
  • Backend API: Python Flask REST API
  • Auction Engine: Java — multithreaded, PriorityQueue, ReentrantLock
  • Database: SQLite — persistent storage for auctions and bids

Platform Features

  • Auction management — creation, activation, termination
  • Bid submission with automatic minimum increment validation
  • Java PriorityQueue for real-time highest bid retrieval
  • Multiple bidder threads for concurrent bidding simulation
  • ReentrantLock concurrency control preventing race conditions
  • Persistent SQLite database storage with recovery on restart
  • Fully responsive interface across mobile, tablet, and desktop
